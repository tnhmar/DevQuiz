# UI-05d part 3d — strict checkpoint envelope decoding
Adds a bounded recovery-checkpoint decoder for the UI-05d outer envelope. It owns parsed JSON, requires exactly the current header fields and payload version, validates nondecreasing creation/update times, and dispatches to the already-added choice/open payload decoders using updatedAt as their capture cutoff. The reconstructed checkpoint is deeply frozen.
The envelope accepts active checkpoints only with null discard metadata and discarded checkpoints only with a discard record whose timestamp equals updatedAt. Discard reasons are explicit user, superseded or incompatible values. A checkpoint ID may not equal the contained session ID. Choice checkpoints require a nonempty session and exact selection/session question snapshot equality; open checkpoints reject a finished state, so completed interactions cannot be revived as resumable work.
This is structural recovery validation only. It does not claim a decoded checkpoint is current, authorized, unexpired, safe to display or eligible to resume; it does not validate a database row/header, pending attempt/save records, receipt state, content activation, catalogue references or provenance beyond the captured structures. It never creates IDs, calls a session engine, replays a save, writes storage or changes discard status.
Next work must validate the persisted checkpoint record/header and its matching pending record(s), reconcile acknowledged/failed saves idempotently, then make a deliberate resume-or-discard decision in the UI. Saved-job rehydration and controls remain separate. Choice/open payload decoding is unchanged and no screen invokes this module yet.
Only this new decoder and notes are added. Existing guards, payload decoders, engines, builders, schema/repository/controller, screens, fixtures, dependencies and workflows are unchanged. No progress aggregation, AI grading, automated authoring or database operation is added.
