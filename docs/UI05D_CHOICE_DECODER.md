# UI-05d part 3b — strict choice state/selection decoding
Adds a decoder for the serialized choice payload inside a recovery checkpoint, not the full checkpoint/outbox envelope. It owns bounded parsed JSON, rejects unsupported engine/selection markers and exact-field mismatches, validates native question shapes and reconstructs the hint registry on a null prototype. It returns deeply frozen session/selection state without creating IDs, calling engine Submit/Next/Restart or accessing a database.
Phase rules require empty/no questions, answering/index prior answers, feedback/current locked answer and finished/all answers with reset current signals. Answer order matches the pinned question order/revisions/families and session/fixture context. Selected option IDs are unique and valid for the captured type. Stored score bits/points are checked against the pinned exact-match definition solely for consistency; no new grade/event or historical record replacement is produced.
Confidence/null time pairs, hint identity/uniqueness/order, reveal time and captures before commit/checkpoint are checked. Confidence after help, changed feedback selections/signals and incompatible assistance/retry flags are rejected, not repaired. Local missed IDs must be within committed IDs, both scoped to captured questions; restart ancestry cannot point to itself. These are local-history consistency checks, not proof of lifetime first attempts or complete prior exposure history. Backwards-clock/out-of-order captures may be rejected rather than assigned fabricated times.
Selection restores the original pinned question list and validates requested/available/selected/shortfall/family counts, type/level/dimension filters, question-family uniqueness and source/shuffle seed shape. Domain/track IDs are retained but cannot be re-resolved without the captured catalogue context; this decoder does not infer reference validity, current activation or publication permission. It does not reselect from a newer bank or reshuffle.
Full checkpoint header/discard/status matching, exact pending AttemptRecord validation/reconciliation, safe saved-job rehydration and resume/discard orchestration remain required before UI resume. Open state decoding is the next small decoder task. No current screen invokes this module; checkpoint persistence/resume and pending-job durability in actual UI use remain unwired.
Only this new choice decoder and notes are added. Existing guards, snapshot builders, engines, schema/repository/controller, screens, fixtures, dependencies and workflows are unchanged. No progress aggregation, AI grading, automated authoring or storage write is added.
Prepared from source already available in the conversation. No repository reads, verification, schema/syntax checks, typechecking, tests, builds, CI inspection, device runs, UUID generation, parsing/validation execution or database operations were performed during preparation; none will be performed after pushing. Decoder fidelity, compatibility, immutability and runtime behavior remain unverified.
