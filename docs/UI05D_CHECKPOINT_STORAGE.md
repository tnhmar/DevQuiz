# UI-05d part 2 — checkpoint-embedded outbox storage
Adds trusted SQLite schema v2 and checkpoint APIs to the existing queued native repository. Version 0 applies v1 then v2 in one exclusive migration transaction; version 1 applies only the new checkpoint table/indexes. V1 attempt DDL/triggers and canonical attempt encoding remain unchanged. Already-open module-lifetime repository handles require a fresh app/module initialization to run the upgraded migration; this source push does not execute it.
Checkpoints are mutable latest-session projections separate from immutable attempt records. They contain the full snapshot and exact pending records together in one JSON value, so an acknowledged checkpoint write persists the current embedded outbox atomically with that snapshot. No separate outbox table or engine restore is added. Basic header/encoding/ownership validation is not the strict engine restore decoder; callers must not feed stored payloads into engines yet.
Save uses expectedRevision (null for first write), starts at revision 1 and advances exactly one revision. Identical retries return already_saved. Stale revisions, changed method/fixture identity, same revision with different content and completed-to-active regressions conflict. Operations share the attempt repository queue and use exclusive transactions/bound parameters. Competing external connections may still produce lock errors; failure is not called durable success.
An earlier pending record must remain byte-equivalent in the next outbox unless an exactly matching immutable attempt row already exists. Unconfirmed records cannot be silently dropped or replaced by new IDs. Attempt append does not automatically edit a checkpoint; later orchestration must reconcile receipts and save the next revision.
Discard sets a terminal non-resumable marker guarded by expectedRevision; no attempt or outbox is deleted. Discarded sessions reject all later checkpoint writes under that ID. Resumable listing returns non-discarded active sessions; outbox listing includes pending records even in completed or discarded sessions. Those records still need receipt reconciliation and must not be hidden merely because a user leaves a session. Explicit privacy erasure/backup lifecycle remains separate.
Only schema/migration integration, the checkpoint repository and these notes change. Existing screens still do not write or restore checkpoints; pending save jobs are still memory-only in actual UI use. Next: expose retained captured records; strict restore decoder and reconciliation; checkpoint receipts plus resume/discard controls for choice/open and earlier retry/capture-failure state. Fixture/subjective flags remain unchanged; no progress aggregation, AI grading or automated authoring is added.
