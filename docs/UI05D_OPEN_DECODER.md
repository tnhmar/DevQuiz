# UI-05d part 3c — strict open state decoding
Adds a bounded open-payload decoder using the existing question/primitive guards and shared content/confidence/equality/freeze helpers. It accepts only open-session-v1 and the current explicit not_captured exposure/retry markers. It owns parsed data, reconstructs criterion-rating maps with a null prototype and returns deeply frozen state without creating IDs or calling engine edit/submit/rate/finish/restart actions.
Writing permits empty text/optional confidence but requires no committed-answer time, submitted-confidence snapshot, rubric ratings or finalized result. Rating requires a nonblank locked answer, commit time and matching submitted confidence; partial ratings may use only captured criterion IDs, and no finalized result may exist. Finished requires every criterion explicitly rated 0/1/2 and a matching finalized subjective result. Zero remains a valid rating, not missing data.
Locked text and confidence/time must agree with the submitted response/result, and commit/capture times cannot exceed the checkpoint cutoff. Result content/session/question/revision/family/fixture identity, objective=false method, rubric keys/values, raw sum/maximum and critical-rating order/values are checked. Totals are verified solely for consistency, not re-rated by the decoder or emitted as a new assessment. No correctness/pass threshold, confidence inference or objective evidence promotion is invented.
The pinned question and model answer are retained. No writing state becomes a submission and no model-answer UI is opened by this decoder; later UI resume must honor its phase. Missing exposure/retry history remains unknown, not unassisted or lifetime-first. Structural approval fields do not establish current activation, fact verification or publication permission.
Full checkpoint envelope/header/discard/status matching, exact pending-record validation, receipt reconciliation, saved-job rehydration and resume/discard controls still follow. No screen calls this decoder yet and actual UI checkpoint recovery remains unwired. Choice decoding is unchanged.
Only this new open decoder and notes are added. Existing engines, guards, builders, schema/repository/controller, screens, fixtures, dependencies and workflows are unchanged. No progress aggregation, AI grading, automated authoring or database operation is added.
Prepared from source already available in the conversation. No repository reads, verification, schema/syntax checks, typechecking, tests, builds, CI inspection, device runs, UUID generation, parsing/validation execution or database operations were performed during preparation; none will be performed after pushing. Decoder fidelity, compatibility, immutability and runtime behavior remain unverified.
