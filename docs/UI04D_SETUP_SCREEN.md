# UI-04d part 2 — setup controls and session integration
Practice now opens a setup view instead of automatically starting the fixed lesson question sequence. A demo-only adapter contextualizes the full existing bundled question array through primary-concept domain/track references and supplies pack/version/language. Missing context shows an unavailable state; no domain or track is guessed.
Controls cover domain, track, level, skill dimension, single/multi/Boolean types, count presets 1/2/5/10/20/50/100 and source/seeded-shuffle order. Changing domain clears the track filter. Preview reports matching questions, distinct families, selected count, excluded family variants and shortages. No matches disables Start. Start is explicitly labelled with the actual available count, never padded or silently broadened. A new shuffle seed does not promise a different permutation for a small pool.
Start passes the displayed selected question list into the existing choice engine with fixture: true. A synchronous start lock is intended to prevent duplicate starts; the session engine copies the definitions. Returning to setup discards the choice session and retains its last started request in memory. Retry repeats the same selected snapshots/order with a new engine session identity; changing selection requires returning to setup. Open self-assessment remains separately linked and never mixed into the choice score.
The setup component and pool adapter are reusable source modules; ordinary content activation is not implemented. The adapter explicitly previews draft demo data and is not an importer, publisher or factual-verification gate. The tiny original bank does not cover all filter values or contain a Boolean example; missing coverage remains visible rather than fabricated.
Only the pool adapter, setup component, Practice screen and these notes change. Both engines, both fixture JSON files, open editor, dependencies and workflows remain unchanged. No persistence, assistance/confidence capture, timers, mastery, AI grading or automated authoring is added.
Prepared from source contracts already available in the conversation. No repository reads, verification, schema/syntax checks, typechecking, tests, builds, CI inspection or device runs were performed during preparation; none will be performed after pushing. Layout, accessibility, selection and runtime behavior remain unverified.
