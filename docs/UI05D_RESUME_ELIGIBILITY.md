# UI-05d part 4a — read-only resume eligibility checker
Adds a minimal, pure function that maps a decoded checkpoint and a small set of external flags to a plain ResumeEligibility verdict with reasons. It does not read storage, call a database, reconcile pending saves, rehydrate saved jobs, change any state or wire resume.
The checker requires the checkpoint to be active (not discarded), an external active-session flag, authorization to access the referenced content, a matching pending attempt/save record, matching receipts and recency within an allowed window. Any failing condition returns ineligible with a single explicit reason. All conditions passing returns eligible.
This is a decision aid only. It does not assert that a checkpoint is current, safe to display, approved for publication or eligible to resume in production; those checks remain the responsibility of callers and surrounding orchestration. No screen invokes this module yet.
Only this new checker and notes are added. Existing decoders, engines, schema/repository/controller, screens, fixtures, dependencies and workflows are unchanged. No progress aggregation, AI grading, automated authoring or database operation is added.
