# UI-04e open-response confidence capture
Adds optional Not provided/Low/Medium/High confidence to the open editor and engine. The existing confidence value type is reused through a type-only import; open scoring remains self_rubric with objective: false.
Confidence may change only during writing. Submit requires nonblank text and captures the original confidence/time in a separate submitted snapshot before model-answer comparison. Confidence and response edits are ignored during rating/finished, so viewing the model answer cannot rewrite pre-submission confidence. Finish copies the submitted snapshot into the subjective result. Null means not provided, not low confidence; confidence does not change criterion ratings or rubric points. Capture timestamps must not follow the answer submission timestamp.
Controls show the captured value while locked and again in the result. Restart clears the response, ratings, confidence and submitted snapshot with a new session identity. Session/question identity guards remain in place. No AI assessment, automatic confidence inference or objective evidence promotion is added.
Only the open engine, open screen and these notes change. Choice practice, setup/selection, hints, fixture JSON, dependencies and workflows are unchanged. This task does not add explicit model-answer exposure events, open retry lineage or cross-session history; those remain separate metadata work before durable evidence use. Model-answer presentation still follows answer submission, and every open outcome remains subjective.
