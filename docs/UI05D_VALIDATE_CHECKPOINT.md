# UI-05d part 4b — persisted checkpoint validation and pending reconciliation
Adds a module that validates the stored checkpoint row/header against the decoded envelope, checks pending attempt/save records against the locked session state, reconciles acknowledged/failed/conflict receipts idempotently and returns a normalized ValidatedCheckpoint plus a list of outstanding jobs. It does not write storage, rehydrate jobs, change discard status or wire resume.
Header validation requires exact identity/version/timestamp/status agreement and discard metadata for discarded checkpoints. Pending validation checks session ID, question ID/revision and answer commit time against the frozen session. Receipt reconciliation accepts upgrades from failed to acknowledged but rejects downgrades and keeps the latest status per pending ID. Outstanding jobs are derived deterministically from pending/receipt state.
This is structural validation and reconciliation only. It does not assert that a checkpoint is current, authorized, unexpired or eligible to resume; those checks remain the responsibility of callers. No screen invokes this module yet.
