# UI-04c part 1 — open-response state engine
A separate memory-only engine uses the existing open-question, submitted-response and 0/1/2 rubric contracts. It does not route self-assessment through the objective choice scorer.
Flow: writing -> rating -> finished. Submit requires nonblank text, captures a supplied commit time and locks the original response. The following UI commit will reveal the model answer and rubric only after this transition. Every criterion needs an explicit 0, 1 or 2 rating; zero is a valid rating, not an unanswered criterion. Finish captures the ratings once. Subsequent edits/submits/ratings/finishes are ignored; restart requires a new session identity. Actions carry session and question ID/revision to ignore stale callbacks.
Question definitions are copied from trusted JSON on creation; callers must treat returned state as immutable. Runtime guards reject unsupported policy, duplicate/empty rubric IDs, missing anchors/model answer and invalid timestamps. This is not an importer, publication validator or factual-verification gate.
Results retain objective: false, fixture context, pack/version/language, question revision/family, original response and answer/rubric commit times. Subjective points are a raw sum out of twice the criterion count, not correctness, mastery, interview readiness or an exam pass. Critical criterion ratings are retained individually; no threshold or automatic cap is invented.
This first commit adds only the engine and scope notes. The open editor, model-answer/rubric controls and clearly labelled original UI fixture follow in the next small commit. Existing choice practice, demo JSON, dependencies and workflows are unchanged. No storage, AI grading, progress events or automated content processing is added.
Existing contracts were read through source commit diffs. No verification, tests, typechecking, schema/syntax checks, builds, CI inspection or device runs were performed during preparation; none will be performed after pushing. Runtime behavior remains unverified.
