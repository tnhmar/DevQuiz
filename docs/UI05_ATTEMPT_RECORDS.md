# UI-05a — immutable attempt snapshots
Starts the persistence milestone with record builders, not database writes. Core UI-04 demo interactions are implemented in source; Boolean demo coverage and open exposure/retry metadata remain follow-ups, and runtime success has not been verified.
Choice builders require exactly one committed answer matching the captured question revision/family/session/fixture context. Open builders require a finished subjective self-assessment matching the locked written response and confidence snapshot. Open record committedAt is the rubric finalization time; both answer and rubric commit times remain in the payload. Intermediate open submissions/checkpoints are not captured by this first builder.
Each flat record is Object.freeze'd and contains only primitive header fields plus JSON snapshot strings. The payload serializes the owned question definition, pack/version/language and committed outcome; later mutation of source objects cannot change that string. Choice payloads also retain hint definitions, exposure/confidence flags and local retry context. Open records remain objective: false and explicitly label model-answer exposure/retry history as not_captured, never unassisted or lifetime-first by default. Level, skill dimension and technology-version scope are retained for future review/evidence separation.
Caller supplies a stable record ID and recordedAt. These helpers do not create durable IDs, guarantee uniqueness, verify factual/publication approval or evaluate evidence eligibility. Fixture flags cannot be overridden through a record option; every fixture remains marked. Native response JSON contracts are unchanged; this is a separate versioned storage projection of trusted engine data, not an external importer or full runtime validator.
Next small tasks: SQLite schema/migration and append-only repository; durable IDs and idempotent saves; screen save/error/retry handling; intermediate submission/session checkpoints and recovery; missing exposure/history metadata before evidence aggregation. Save retries must reuse the same record identity and exact captured payload rather than reconstructing a new attempt. Historical snapshots must not be overwritten by later content edits or rubric changes.
Only the new src/storage/attempt-records.ts and these notes are added. No database is opened, migrated or written. Existing source/storage/schema files, screens, engines, fixtures, dependencies and workflows are unchanged. No demo data is promoted to progress; no AI grading, mastery aggregation or automated authoring is added.
Source-directory/root layouts were read for integration. No verification, schema/syntax checks, typechecking, tests, builds, CI inspection or device runs were performed during preparation; none will be performed after pushing. Immutability, compatibility and runtime behavior remain unverified.
