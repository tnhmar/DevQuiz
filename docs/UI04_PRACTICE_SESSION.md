# UI-04a — reusable choice practice-session engine
Pure memory-only state transitions for single/multi/Boolean choices. Inputs explicitly identify session, content pack/version/language and fixture context. Question definitions are copied from trusted JSON data on creation; callers must treat returned state as immutable. The engine is not an external JSON importer, publication validator, exam simulator or persistence layer.
Phases: empty, answering, feedback and finished. Selection is not commitment. Submit produces one scored answer; duplicate submissions in feedback are ignored. Actions carry question ID/revision, so stale taps after Next cannot skip another question. Invalid option IDs are ignored. Next requires feedback; restart requires a new session ID and clears local answers while retaining the question snapshots.
Creation rejects unsupported open-response/scoring configurations and duplicate question IDs; these are application runtime guards, not checks executed during this commit's preparation. Existing scoreChoice handles exact-match options by ID. No hints, confidence, timers or rubric outcomes are inferred. The separate open-response flow, UI binding, assistance/exposure capture, durable storage and evidence aggregation follow in small tasks.
Fixture answers are explicitly marked and summaries are temporary performance counts, not mastery or readiness. No SQLite writes or progress events occur here. Content approval/eligibility is the caller's responsibility before a non-fixture session. Source field assertions do not establish factual correctness.
This commit adds only the engine and these scope notes. Existing demo screen/content, dependencies and workflows are unchanged until the next UI binding commit.
No repository inspection, verification, typechecking, schema/syntax checks, tests, builds or CI runs were performed before preparing this commit; none will be performed after pushing. No runtime success is claimed.
