# UI-05d persisted-format recovery correction
Reconstructed storage contracts from commit history through ce2b2dac16dc49aff710737d594e081a58a5454a. Attempt records originate in bf7e16c, repository encoding in 920aa1f, stable controllers in 65121ca, checkpoint snapshots in cce074f and checkpoint storage/migration in 8af8f85. Later storage commits add guards/decoders and the incompatible 3d/4b path; they do not change those original persistence contracts.
The actual StoredCheckpoint is { checkpoint, discarded }, with schemaVersion=1, sessionId, kind, revision, fixture, active/completed status, updatedAt, pendingCount and snapshotJson. Its inner devquiz.recovery.v1 envelope contains the full payload and full pending AttemptRecords. There is no stored checkpointId/createdAt/ui-05d-v1/discard-reason envelope. This new path reads that real contract and does not use recovery-checkpoint.ts, validate-checkpoint.ts or resume-eligibility.ts. Those legacy additions remain unwired and must not be treated as compatible production restore gates.
The decoder owns bounded JSON, matches every persisted projection field to the body, dispatches through the existing engine decoders, checks session/fixture/completion identity, rejects duplicate record IDs/logical outcomes and freezes its output. Pending records are checked against builders using their original supplied recordId and recordedAt. This reconstructs an expected snapshot solely for comparison: it does not call engine actions, regrade into a new event, create an ID/time or replace stored strings. Full parsed payload/scope equality is required, while original payloadJson and technologyScopesJson strings are retained byte-for-byte. Header fields must exactly match.
Reconciliation requires one explicit lookup observation for every pending record, with recordJson set to a serialized findById result or null for an acknowledged successful lookup finding no row. A failed/unknown lookup is not null and must block the caller instead of being passed here. Unknown/duplicate/missing observations and any saved-record mismatch reject the whole operation. Exact saved matches are acknowledged and never outstanding; only explicit no-row observations remain outstanding. Comparison with a saved row includes exact original snapshot strings, not merely semantic JSON equality. No fabricated receipt timestamps or failed/acknowledged flags are used.
Completed and discarded checkpoints retain outbox processing; their sessions are not made resumable. Empty active sessions or empty outboxes are structurally allowed and need separate UI eligibility policy. A lookup is not a transaction-wide guarantee: later concurrent writes and a different record ID for the same logical outcome remain protected by the repository's final append conflict check. Caller observations must come from the trusted repository, not user-supplied claims. This decoder is not an integrity proof against tampering or publication/activation permission.
Only this new source module and notes are added. Controllers, older decoders, builders, repository/schema, screens, dependencies and workflows are unchanged. No controller is rehydrated, no record is appended, no checkpoint is revised/discarded and no screen calls this path. Outstanding records are immutable inputs for the next controller adapter, not executable jobs.
