Adds explicit restore constructors that consume already-decoded app-owned checkpoint state. Choice restore checks session/content identity, phase/index/answer count, pinned order and question revisions, exact stored scoring consistency, selected option validity, confidence/help timing, retry-flag structure and selection snapshot identity/family uniqueness. It deep-copies before returning. It does not call score-and-commit reducers, create attempts/UUIDs/timestamps, alter result flags or reselect questions. Score calculation is used only to reject an inconsistent stored result against its captured pinned question.
Open restore preserves writing/rating/finished phase, original written text, submitted-confidence snapshot, partial or complete ratings and result. It rejects identity/revision/method/time inconsistencies, missing/extra rubric entries where phase requires completeness, invalid rating values and a finalized result inconsistent with the captured locked response. It does not submit writing, reveal content, rate, finish, recompute points as a new result or infer subjective/objective evidence. Finished totals are checked as a consistency guard only.

This change marks valid active writing/rating open snapshots as candidates while still excluding finished/completed and discarded sessions. A candidate is not permission to resume: local fixture policy, content pin compatibility and explicit UI choice remain separate. Sessions with zero pending attempts remain eligible candidates. Outbox entries for completed/discarded sessions remain independently visible.
