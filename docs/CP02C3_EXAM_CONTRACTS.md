# CP-02c3 — test and exam-profile contracts
Scope: structurally typed exam profiles, fixed/rule-based tests, timing, selection filters/objective weights and distinct official-scoring/app-benchmark records. This is not the exam engine, a verified credential catalogue, a readiness gate or an importer.
Profiles record provider/credential/code, standard/renewal/unknown variant, lifecycle, preparation stage, declared verification, official source IDs, required/recommended prerequisites, language availability, objectives/mapping/weights, count range, duration, supported choice types, required capabilities, navigation, review and retirement dates. Unknown metadata is explicit null/unknown, never fabricated. Vendor languages may exceed the app's EN/FR content support. Unsupported interactions can be described by requiredCapabilities but cannot be silently simulated; readiness is a later gate.
Official scoring is exactly one of percentage, points, scaled or unknown. Scaled has minimum/maximum/passingScore, not passingPercent. App practice percentage benchmark is separately labelled app_practice_benchmark. No conversion from vendor-scaled score to raw percentage. Cross-field range/order/score relationships, objective-weight sums, real official evidence, compatibility and stale/retired rules belong to CP-03/04 and the exam engine.
Tests have kind=test, editorial metadata, practice/simulation mode, profile ID/revision, timing and scoring declarations. Exactly one of questionRefs or selectionRule is present. Fixed IDs and filter arrays do not prove a question bank exists. Rules include count, domain/track/concept filters, level/dimension/version scope and objectiveWeights; objective IDs refer to blueprint objectives, not generic app domains. CP-03 owns these links, quotas, sums and sufficiency. Choice and open scoring policies remain separate.
Simulation shape requires non-null profile ID/revision and timed pauseAllowed=false; this declares timing policy but does not implement a deadline. Practice may be untimed or pausable. Standard/renewal identity and actual timing/scoring snapshots must be retained by future attempts. Unscored vendor items, case-study relationships, accommodations and unsupported interactions cannot be inferred from these structural declarations.
Validators reuse trusted block/question/learning/provenance schemas. Every report returns referencesChecked=false, profileMetadataChecked=false, simulationReadinessChecked=false and publicationChecked=false. A self-declared simulation_ready record is still unchecked. No coercion, defaults, field stripping, network fetches or pack-provided schema.
Files: schemas/exam-entities.v1.schema.json; src/content/exam-entities.ts; src/content/exam-entity-validator.mjs; scripts/exam-entities.test.mjs. Package/envelope/app remain unchanged; composed integration is CP-02d. Fixtures are original artificial metadata, not real credential information or learning content.
Tests are source only. No checks/tests/repository reads/CI inspections/device verification were run for this task; none will run after pushing. Future explicit command, not run here: node --test scripts/exam-entities.test.mjs.
