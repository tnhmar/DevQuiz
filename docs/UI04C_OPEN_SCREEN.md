# UI-04c part 2 — open-response demo screen
Adds the standalone /practice-open route and an original local UI-only fixture. The next small navigation commit will link it from Practice; existing choice practice is unchanged here.
The screen uses the part-1 open engine, a multiline editor with a 100000-character limit and a nonblank-submit requirement. Submission locks the response and reveals the model answer, explanation and per-criterion 0/1/2 anchors. Every criterion requires an explicit self-rating before Finish; zero counts. Finished ratings lock. Critical ratings remain visible individually with no invented passing threshold or cap.
Synchronous state refs and engine session/question identity guards are intended to ignore duplicate/stale callbacks. Errors show an unavailable state and restart control. Restart clears the local answer and ratings with a new process-local session identity. Back explicitly discards this open demo. Keyboard, accessibility and layout behavior are source intentions, not verified device behavior.
The completion view labels the rubric sum as subjective self-assessment, never objective correctness, mastery, interview readiness or an exam pass. No AI grading, SQLite writes, progress events, reminders, timers or automated content processing is introduced.
The new demo-open.en.json is a local fixture wrapper around the existing typed open-question shape, not a native content pack or runtime import/approval mechanism. Its TypeScript assertion does not prove schema validity, referential integrity or publication permission. It contains only original interface instructions, no real course/book/vendor questions. The original demo.en.json, dependencies and workflows are unchanged.
No repository reads, verification, schema/syntax checks, typechecking, tests, builds, CI inspection or device runs were performed while preparing this commit; none will be performed after pushing. Runtime behavior remains unverified.
